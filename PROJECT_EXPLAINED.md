# Как устроен детектор дронов YOLOv8s

Это лабораторная работа по детекции объектов. На вход модель получает изображение, на выходе даёт рамки с классом `Drone` и оценкой уверенности. За основу взята YOLOv8s с весами, предобученными на COCO. На этих весах проведено дообучение для одного класса.

## Что сделано

1. Подготовлена исходная разметка Roboflow. Из 343 фотографий выделено 241 для обучения, 51 для валидации и 51 для теста.
2. Проведены первые запуски с разбиением по роликам. В этом режиме тест содержал преимущественно мелкие дроны, а обучающая выборка — более крупные. Затем кадры перераспределены случайно внутри групп по размеру, чтобы в каждой выборке были объекты разных размеров.
3. Текущая модель дообучена на RTX 4050 за 30 эпох. Выполнены тест на размеченных кадрах и ручная проверка на 10 интернет-фотографиях с дронами и 10 фотографиях без них.
4. Для сравнения из YOLO-раздела репозитория Hugging Face выбраны ещё 343 размеченных изображения, включая 241 для обучения. Новая модель стартовала с тех же весов COCO. Изображения проверялись на точные и близкие совпадения по хешам. Обе модели прогнаны на двух тестах и на тех же веб-фото. [Источник Hugging Face](https://huggingface.co/datasets/Leofierus/Drone-Dataset/tree/fd51b82097f510f8ebb8debb08f021e640c5f352).

## Как работает код

### Подготовка данных

[`prepare_dataset.py`](prepare_dataset.py) сопоставляет каждому изображению из `dataset/train/images` текстовый файл с таким же именем из `dataset/train/labels`. Строка YOLO-разметки имеет вид `class_id x_center y_center width height`. Координаты и размеры нормированы относительно ширины и высоты изображения. Единственный класс имеет индекс `0`.

Скрипт проверяет координаты и преобразует три полигональные аннотации в прямоугольники по крайним точкам. Он записывает рабочие копии в `dataset/detection`, а исходный экспорт остаётся в `dataset/train`. SHA-256 декодированных пикселей используется для поиска точных дубликатов. Кадры сортируются по медианной относительной площади рамок, делятся на три группы и перемешиваются внутри каждой группы с seed 42. Из каждой группы по 17 кадров попадают в валидацию и тест, остальные — в обучение. [`data.yaml`](dataset/data.yaml) указывает на три итоговых списка файлов.

### Обучение и тестирование

[`train.py`](train.py) загружает `yolov8s.pt` и вызывает `model.train(...)` с размером входа 512, пакетом из 8 изображений и 30 эпохами. Во время обучения модель обновляет веса на train и вычисляет метрики на val. Ultralytics сохраняет `best.pt` по лучшему mAP@50–95 на val. Затем скрипт загружает этот файл и вызывает `model.val(split="test")` на отдельном списке. Он записывает метрики в JSON, строит график и сохраняет пять тестовых изображений с предсказаниями.

### Инференс

[`infer.py`](infer.py) принимает путь к изображению, папке или видео. По умолчанию загружает `runs/drone-random/weights/best.pt` и выводит рамки с уверенностью от 0,25. Параметр `--weights` задаёт другой файл весов, `--conf` меняет порог, а `--device 0` выбирает первую видеокарту. `stream=True` позволяет обработать видео по кадрам. Результат записывается в `runs/predict` или следующую папку с номером.

Пример запуска из корня проекта в PowerShell с уже установленной локальной CUDA-сборкой:

```powershell
$env:PYTHONPATH = (Resolve-Path .cuda-packages).Path
python infer.py "try/01.jpg" --device 0
python infer.py "try/01.jpg" --weights runs/drone-hf/weights/best.pt --device 0
```

## Как читать результаты

**Precision** показывает долю корректных детекций среди предсказанных рамок. **Recall** показывает долю найденных объектов среди всех размеченных. **mAP@50** суммирует качество по кривой precision–recall при совпадении рамок с IoU от 0,5. IoU — это площадь пересечения рамок, делённая на площадь их объединения.

| Тестовая выборка | Обучающая выборка | mAP@50 | Precision | Recall |
| --- | --- | ---: | ---: | ---: |
| Локальная | Локальная | 0,982 | 0,959 | 0,981 |
| Локальная | Hugging Face | 0,611 | 0,752 | 0,509 |
| Hugging Face | Локальная | 0,578 | 0,577 | 0,593 |
| Hugging Face | Hugging Face | 0,934 | 0,928 | 0,878 |

Для эксперимента Hugging Face использованы пары изображений и текстовых аннотаций из каталога `drone_dataset_yolo/dataset_txt`. Формат меток совпадает с локальным. [`dataset/huggingface/data.yaml`](dataset/huggingface/data.yaml) описывает отдельное разбиение. Для каждой пары «веса и тест» оценка запускалась через `model.val(split="test")` с размером входа 512. Текущий `train.py` настроен на локальный датасет. Для модели Hugging Face в проекте сохранены подготовленные данные, веса и результаты сравнения.

Каждая модель показала лучшие метрики на тесте из своего источника. Медианная рамка дрона в обучении Hugging Face занимает 34,2% кадра, в локальном наборе — около 3,0%. В локальном разбиении похожие кадры одного ролика могут попасть и в обучение, и в тест. Поэтому результат 0,982 характеризует этот набор отложенных кадров, а оценка на новых роликах требует отдельного теста с разбиением по источникам видео.

На веб-фото при пороге 0,25 локальная модель выдала рамки на 8 из 10 снимков с дронами и на 4 из 10 снимков без них. Модель Hugging Face выдала рамки на 10 из 10 снимков с дронами и на 6 из 10 снимков без них. Это подсчёт снимков с хотя бы одним срабатыванием, включая ложные и повторные рамки.
